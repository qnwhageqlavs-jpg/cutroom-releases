# CUTROOM 操作手册

适用版本：**0.9.0-beta.14（Beta 版）**。本手册按页面操作介绍数字人混剪和信息流广告混剪，供制作视频的同事使用。

[下载安装包](https://github.com/qnwhageqlavs-jpg/cutroom-releases/releases/tag/v0.9.0-beta.14) · [遇到问题](#troubleshooting) · [发布前检查](#checklist) · [已有任务升级](#upgrade) · [连接 WorkBuddy / 豆包工作](#agent-mode)

<a id="routes"></a>

## 先选制作路线

| 路线 | 适合的情况 | 声音与画幅 |
| --- | --- | --- |
| 数字人混剪 | 已有数字人口播 MP4，希望加字幕、补充画面和包装 | 保留口播原声，默认按 1.25 倍速制作；竖屏 9:16 |
| 信息流广告混剪 | 已有文案和图片、视频，希望自动配音并组合画面 | 使用本片选定的配音服务和音色；竖屏 9:16 或横屏 16:9 |

园区宣传片专用路线暂未开放。CUTROOM 导出 MP4、封面、发布文案及检查报告；不自动上传平台，不提供剪映原生可编辑工程。

**先从一条素材齐全的短视频开始。** 最终文案、画面顺序、包装方案和成片都需要你确认，AI 建议不能代替这些决定。

## 安装与每天打开

### 首次安装

1. 打开公开下载页，无需登录 GitHub，在 **Assets** 中下载 Windows ZIP；不要下载 **Source code**。
2. 完整解压到自己可写的短路径，例如 `D:\CUTROOM`。
3. 保持联网，双击 **安装CUTROOM.bat**。看到“安装完成”前不要关闭窗口。
4. 双击 **启动CUTROOM.bat**，等待浏览器打开工作台。

需要 Windows 64 位、联网和软件安装权限。安装器会准备 Python 3.11、Node.js LTS、FFmpeg 等必要组件；无需自己写代码或逐个安装依赖。提示缺少 `winget`、权限不足或环境不完整时，保留错误信息并联系维护人员。

### 日常使用

- 每次双击同一个安装目录中的 **启动CUTROOM.bat**；不要移动整个安装目录。
- 使用启动入口打开的页面。提示“未授权”时重新运行启动入口，不要只反复刷新网址。
- 关闭浏览器不会取消正在处理的任务；再次打开后，在任务中心查看进度。
- 需要中止时，使用页面提供的“安全暂停”或取消操作。已发出的模型请求仍可能产生费用。

已有任务的用户先阅读[升级、回退和卸载](#upgrade)。原位升级保留原任务；换电脑或换目录另按维护流程迁移。

## 首次设置：账号、能力与音色

打开 **设置 → AI 服务连接**。先添加供应商账号，再配置需要的能力，最后检查检测结果。没有账号或不清楚开通范围时，请负责模型服务的管理员协助。

| 能力 | 什么时候需要 | 怎样选 |
| --- | --- | --- |
| 文案策划 | 使用“CUTROOM 自己规划”时，用于文案、分镜和包装建议 | 选择已开通的文本模型，填写供应商提供的准确模型名称或接入点 |
| 配音 | 信息流广告需要；数字人使用原声 | 选择已开通的配音服务，在中文音色目录中选常用声音 |
| B-roll | 本地画面不足、需要生成补充视频时 | 可选；已有合适素材时不必配置 |
| 视觉服务 | 希望分析素材画面或使用模型辅助内容检查时 | 可选；按设置页完成检测后再使用 |

### 豆包配音怎样填写

- **豆包 API Key**用于合成、试听和连接检测。
- **AK/SK**用于自动刷新音色目录，即 Access Key ID 和 Secret Access Key。
- **AppID + Access Token**属于旧版兼容，新版账号可以留空。
- 按账号实际开通情况选择配音服务版本，再从中文名称列表选择音色。常用音色只是新广告的预选项，创建时仍可更换“本条视频音色”。

**“保存并检测”会生成极短的测试语音，可能计费。** 等待结果后再操作，成功后不用重复点击。密钥由当前电脑、当前 Windows 用户的凭据管理器保存，不需要修改配置文件，也不要把密钥发到群里。

新任务只能选择检测有效的配置；超过 24 小时会提示重新检测。任务创建后保留本次选择，后来修改默认模型或常用音色不会自动改变旧任务。

如果音色目录为空、提示缺少 AK/SK 或没有权限，请先处理账号配置。详细字段和账号权限见[供应商配置说明](../operations/model-profiles-new-api.md)。

## 准备并登记镜头素材

镜头素材是实际使用的图片和视频，可以保存在本机硬盘或移动硬盘。建议把不同项目分开存放：本片专属画面放“主素材”，可跨项目使用的城市空镜、交通、办公等放“通用补充素材”。

1. 打开 **镜头素材**，登记实际文件夹，填写容易识别的名称及用途。
2. 首次添加目录后会自动开始扫描，等待完成即可。以后新增或更改文件，再点击 **检查更新**。
3. 创建任务时选择本次主素材目录，再按需勾选通用补充目录。

扫描包含本目录及各层子文件夹中的支持格式素材。扫描期间显示等待或正在扫描，按钮暂不可重复提交；完成后自动更新目录数量和下方台账，无需刷新页面。台账仍按当前任务范围和筛选条件显示。若出现“刷新扫描状态”，点击只读取原任务，不会再次提交扫描。目录扫描是登记文件，不等于完成画面内容分析。

登记不会移动或重命名原片。新增文件后再检查更新；移动硬盘盘符或目录位置变化时使用 **重新连接**，不要删除旧库后重新登记。

制作前确认素材在线、有足够可用时长，且画面方向适合本片。横版任务不要依赖竖版素材自动变成合适的横版画面。未取得使用权、含隐私或归属不清的文件先不要用于正式任务。

## 七步完成一条视频

| 页面 | 本步的结果 |
| --- | --- |
| 01 创建任务 | 路线、输入、模型与素材范围确定 |
| 02 文案确认 | 最终文案确认；数字人口播完成核对 |
| 03 分镜推荐 | 每段文案搭配的画面形成初稿 |
| 04 粗剪调整 | 声画顺序与取用区间确认、画面锁定 |
| 05 包装方案 | 字幕、音乐等包装经过真实预览并确认 |
| 06 成片审查 | 当前成片检查、完整观看并确认通过 |
| 07 交付发布 | 封面与发布信息核对后导出交付文件 |

点击已完成步骤可以回看；尚未开始的步骤不能直接跳过。历史页面显示只读时，请回到当前步骤，或使用页面提供的修改、返工入口。

### 01 创建任务

点击 **新建视频**，选择数字人混剪或信息流广告混剪。

- **数字人**：选择最终口播 MP4、规划方式及素材目录。文案在下一步填写，使用视频原声，不选广告配音音色。
- **广告**：选择横屏或竖屏、规划方式、配音服务、**本条视频音色**及素材目录。可以先试听音色；文案同样在下一步填写。

普通页面操作选择 **CUTROOM 自己规划**。已有维护人员配置 Agent 连接时，也可选择“当前 Agent 规划”，见[Agent 协助](#agent-mode)。

完成创建前预检，处理页面指出的问题，再创建任务。改变视频、素材或配置后先重新预检。创建过程中连接中断时，先检查任务中心是否已创建，不要反复修改表单重新提交。

### 02 文案确认

**数字人路线：** 填写与 MP4 口播一致的文案，播放原声核对；也可试听制作速度。确认后点击 **确认与口播一致，继续**。系统转写核对后若提示数字、否定词或漏句疑点，按时码回听：文案错了就改稿，视频错了就更换底片并重新核对。

**广告路线：** 填写最终文案，保存、通读，再点击 **确认文案，继续**。确认文案本身不会立即生成配音；进入后续规划和声音生成时，再按页面确认调用。视频时长以实际生成的配音为准。

保存草稿不等于确认。需要改已确认文案时，使用 **修改文案** 并查看影响；已有候选成片时先在审片页记录返工。旧声音、画面和包装可能需要重新检查，页面会列出受影响内容。

### 03 分镜推荐

按页面发起分镜处理，检查每段文案和建议画面是否对应。素材检查未完成时先等待；若提示源文件变化，点 **查看素材变化**，核对后再同步。

有可用的已生成结果时，使用 **恢复已生成分镜**，避免重新发起模型调用。选好初步画面后点击 **生成粗剪**。素材较多时，后台完整核验可能需要数分钟；刷新只查看已有进度，可以先回任务中心。

缺少画面时点 **查看缺口处理清单**，按[缺画面的处理方法](#gaps)补齐。数字人可保留原人物画面；广告需要为每段配好真实可用的画面。

### 04 粗剪调整

先连续播放，再逐个点击镜头，检查旁白、画面和字幕是否配合。

- **更换或增加画面**：点“更换镜头”或“后面添加镜头”，搜索并翻页查看候选。先选中并预览，再按替换或应用按钮确认；仅点选候选不会改片。
- **调整取用区间**：视频镜头可调整原片取用起止位置；图片不做视频入点、出点裁剪。区间过短、越界或文件离线时，先修正再保存。
- **调整镜头安排**：在页面允许的范围内增删、调整顺序或撤销操作；保存前核对影响。

数字人以原口播为声音主轴，换成补充画面仍保留原声；不能单独裁剪原人物画面来改变口播时间。广告须保证镜头时长覆盖配音，且素材有转场所需余量。

核对完成后点击 **确认粗剪并锁定画面**。有缺失镜头或主声不可用时，先解决页面提示的问题。

### 05 包装方案

选择推荐方案或本片草稿，检查字幕、背景音乐，以及需要启用的标题、信息卡、Logo、水印、贴纸、花字和音效。

1. 为本片填写实际文字、选择素材，并设置出现位置和时间。不需要的可选类别直接关闭。
2. 点击 **生成真实预览**，观看预览提供的全部片段并试听声音。预览是成片的部分片段，不代表已经看完最终成片。
3. 发现遮挡、字太多、音乐压过人声或素材不合适时，修改后重新生成并观看预览。
4. 当前方案的预览观看满足要求后，点击 **确认方案，生成成片**。

方案修改后旧预览会失效；不能直接用旧预览确认新方案。使用“保存为我的方案”可保存可复用的样式和规则，新任务仍须重新填写本片文字、生成预览并确认。

### 06 成片审查

先处理自动质检的阻断项，再从头到尾播放当前成片。重点检查读音、字幕同步、画面匹配、转场、人声与音乐、事实、隐私和素材使用权。

发现问题时点击 **记录问题**，填写问题类型和说明。记录会绑定当前版本及时间点；可点 **定位问题** 回看，再点 **去修改** 进入返工。未处理的人工问题会阻止批准。历史成片可以回看，不能代替当前版本的审片。

**最终文案、画面顺序、本片包装方案、完整观看后的成片确认，这四次人工确认都需要完成。** 自动质检通过、模型没报告问题，都不能代替你的观看判断。

确认素材来源时按真实情况选择：全部为团队自摄且可商用，才选择团队自摄登记；第三方素材已获本片授权时，仅确认用于本片。补齐授权后按页面重新检查或生成候选，不会自动消除旧报告。

### 07 交付发布

1. 选择本版成片提供的封面，或选择已有外部图片。
2. 核对发布标题和文案，必要时修改；不要把“封面待补”当作已经可发布。
3. 确认保存位置。需要时点 **更换目录**，选择已有、可写的本机文件夹。
4. 点击 **导出交付包**，等待完成，再点 **打开交付目录** 查看实际文件。

标准交付包含：最终视频 `video-final.mp4`、三张封面、发布文案 `publish-copy.md`、发布检查文件 `publish-check.json`、质检报告 `qa-report.md`，共七个文件。选择外部封面时会额外保留所选图片。

主要使用最终 MP4、选定封面和发布文案；检查文件留作交付记录。需要自行到目标平台上传。素材组件及时间映射不等于剪映原生工程。

## 调整广告读法与本片声音

适用于广告任务。数字人任务使用底片原声，读错时应修正文案或更换口播视频。

1. 在已保存并确认的广告文案中，选中需要调整的完整词句，点 **读法与试听**。
2. 修改读法，或按需要选择本片音色。读法文本用于配音，字幕仍显示原文；当前不支持通过该入口安全替换数字读法。
3. 发起试听前，核对页面显示的待生成次数及费用，并明确确认。
4. 等待生成，试听读音和两句衔接；满意后点 **应用到本片**。生成成功不会自动应用。
5. 根据页面提示重新确认受影响的分镜、画面和包装，再审看新成片。

修改一句时可能复用其他有效句；换音色通常需要重新生成各句。打开 **历史声音** 可以试听并恢复可用的旧声音，恢复使用已有文件，不新增配音调用，但不会恢复旧成片的批准。

生成中使用 **刷新试听结果** 读取原作业。结果未知或素材变化时先核对，不要反复收费生成。

<a id="text-edit"></a>

## 用文字辅助修改镜头

在粗剪点 **文字修改**，输入具体要求，例如“删除第3个镜头”，再点 **生成修改草稿**。先检查镜头前后变化、时长和影响，再确认应用；不满意可取消，应用后可按页面撤销。

需要 AI 帮忙理解要求时，展开 **AI 理解修改要求**，按页面选定镜头并确认发送及费用。返回后点 **选择此解释，预览差异**，检查后再 **确认修改**。

目前只支持页面允许的部分剪辑操作，不是任意一句话都能完成。要求不清楚或缺少依据时，改用手动调整；不会自动替你批准成片。

<a id="gaps"></a>

## 缺画面与节奏建议

在分镜、粗剪或本任务素材页打开 **查看缺口处理清单**，先看每项缺口的具体原因。

| 提示 | 怎样处理 |
| --- | --- |
| 未分析或尚未登记 | 先检查更新、分析素材或补充人工标注，再重新核验 |
| 素材离线 | 接回原硬盘，用重新连接恢复 |
| 方向不合适、时长不足 | 选择画幅合适、连续时长足够的素材 |
| 重复分配或片段不可用 | 调整镜头或可用区间，再核验 |
| 没有匹配内容 | 先看现有候选；确实没有合适画面时再安排补拍 |

**“已有候选”不等于已用进片子。** 预览、采用合适画面后，再点“重新核验”；清单检查本身不会自动替换镜头。

AI 补画面建议可在写清实际需求后 **加入缺口清单**。人工登记的需求可展开 **修改需求**，填写新需求和原因，再 **保存并重新核验**；自动生成的需求不能在这里改写。

粗剪的 **节奏检查与建议** 提供复看线索。先“定位镜头”，再决定是否看修改草稿或手动调整。低音量区间、短镜头比例只是线索，音乐和衔接是否自然仍需试听。

<a id="packaging"></a>

## 使用包装素材和自己的音乐

“包装素材”可浏览字幕与字体、音色、音乐、音效、文字卡、信息卡、贴纸、花字和 Logo / 水印。进入本片包装方案后再选择实际使用的组合。

- **个人包装目录**：在“设置 → 存储与缓存”选择位置。切换位置不会搬走旧文件；普通包装文件放进目录后仍需维护人员登记，不能仅凭复制文件就用于任务。
- **自己的音乐**：在本片“背景音乐”展开 **我的本地音乐库**，点 **连接音乐文件夹**。读取后搜索、试听、确认曲目使用权，再返回本片选曲。新增音乐后“重新扫描”，位置变化用“重新连接”。
- **音量**：有建议时，点击 **使用建议音量** 才会修改。调整后重新生成预览并试听，不要只看数值。
- **音效**：选择出现的事件或镜头，必要时在“精细调整”中设置素材内起点、播放区间、音量和淡入淡出。区间超过真实素材长度时要缩短或换素材。
- **恢复已关闭元素**：关闭可选元素会保留设置。重新启用后检查素材是否还在线，并重新生成预览。

带署名要求的音乐需在发布说明等合适位置保留署名，具体见[第三方素材说明](../../THIRD_PARTY_NOTICES.md)。

## 素材搜索、分析和 Excel 台账

### 搜索与分析

素材台账可按任务、目录或用途筛选，再搜索文件名、画面描述、标题或标签。按画面内容搜索依赖已有观察或人工标注，没分析过不代表没有这段内容。

可逐项勾选素材，或点击表头 **全选本页**；全选后再次点击可 **取消本页全选**。只选择本页在线且可用的视频、图片，其他页的选择保留；部分选中时显示半选状态。每次分析仍最多 50 项。勾选后点 **分析选中素材**。系统先在本机整理场景候选；如果继续使用视觉模型，先核对批次、发送范围和费用，再点 **开始本批分析**。分析只覆盖取样范围，仍需打开片段观看。

费用确认仅用于当前预览和本次提交。同一预览刷新会保留勾选，提交后显示“本批费用已确认”与“本批分析中”。结束后显示成功（含复用）、失败、未完成数量；“本批已结束”不代表全部成功。全部成功时显示“本批分析已完成”。如需重试，点击“准备重试未完成项”，重新检查范围并勾选费用确认后再开始；切换批次或视觉服务也需重新确认。VISUAL_PROTOCOL_INVALID 表示服务返回结果格式不符合要求，该项尚未生成可用分析结果。

本机检测进度分别显示已完成、失败、检测中或等待的数量。场景划分完成但画质检测未完成时显示“等待画质检测完成”，不计入已完成，也不标为失败。任务停止后未完成项可重试；实际失败保留具体阶段及原因。

抽样偏暗、疑似重复或运动判断不能直接决定素材是否可用。你可以核对后修改片段使用标记；本功能不会自动清空或整理原素材库。

### Excel 台账

点击 **导出 Excel 台账**，获得当前筛选范围的记录。只改浅黄色可编辑列，保留资产、可用片段两张表和只读字段；不要加入公式、宏或外部连接。

修改后点 **导入 Excel 台账**，先看差异与冲突，再 **应用这些变更**。删掉表格行不会删除原素材；要停用应修改使用状态。出现版本冲突时重新导出当前数据再核对，避免覆盖其他人的修改。

<a id="ai-review"></a>

## 可选：AI 辅助审片

### 模型辅助内容检查

在成片审查展开 **模型辅助内容检查**，按页面选择可用服务，核对发送范围与费用后开始。当前会发送有限成片抽帧和文案，不检查所有连续画面。

模型指出问题时，先定位回看，再“去修改”；有具体依据决定保留本版时，填写说明并 **确认保留**。检查失败或覆盖不足时，按页面要求完成技术质检、完整观看和问题处理后，可 **确认人工接管**。接管不代表模型检查通过。

### AI 声音检查（试用）

当前候选质检合格且尚未批准时，可展开 **AI 声音检查（试用）**，加载需要检查的区间，选择已配置账号，确认发送及费用后开始。单次最多检查 30 秒，发送所选成片音频和指令，不发送文案或画面。

**“返回文字待复核”不表示检查通过。** 当前完整 AI 听审尚未验收，语气、重音、情绪、读音及衔接仍需自己试听。声音检查不是出片必经步骤；它不会自动批准视频。

刷新只读取原结果。候选或输入变化后，旧结果仅供历史参考；结果未知时保留原请求，不通过换任务或反复点击绕过提示。

<a id="error-feedback"></a>

## 出错后怎样反馈

CUTROOM 会在本机自动保留近期错误。出现红色提示、操作失败或页面异常时，不必先反复重试。

1. 点击页面顶部的 **导出报错日志**。窄屏下在导航菜单中找同名按钮。
2. 把下载的 `CUTROOM-errors-….zip` 发给维护人员，并说明 **大约几点、在哪个页面、刚才点了什么、预期什么结果**。可附错误截图，截图不要包含密钥。
3. **安装失败或网页打不开：** 在 CUTROOM 安装目录双击 **导出报错日志.bat**。文件生成在该目录的 `out` 文件夹，导出后会打开位置；不需要先把工作台启动起来。

网页失去连接或授权时，按钮会先下载 `…-browser.json`，它仅含浏览器侧记录。请再运行上述 BAT，把两份文件一起提供。Python 还没有安装完成时，BAT 可导出安装/启动记录，包内会说明覆盖范围。

日志默认只保存时间、版本、错误类别、接口类别及程序代码位置，不包含 API Key、访问令牌、请求或响应原文、任务文案、素材和数据库。日志不会自动上传，导出后由你决定发给谁。后台日志约保留最近 1 MiB，浏览器保留最近 40 条；尽量在出错后及时导出。

此功能覆盖新版程序捕获到的安装、启动、接口、网页和后台作业错误。断电、磁盘无法写入、程序尚未加载或使用旧版时，可能没有记录；这时请提供截图和当时操作，不能把“没有日志”理解为“没有出错”。

## 遇到问题怎么办

| 情况 | 先做什么 |
| --- | --- |
| 工作台打不开、提示未授权 | 重新双击原目录的“启动CUTROOM.bat”；确认没有移动目录 |
| 安装提示环境不完整 | 保留错误窗口和原目录，联系维护人员；不要删除任务或搬动运行环境 |
| 模型不可选、检测过期 | 检查账号、服务开通和检测结果；明确费用后再检测 |
| 任务一直处理中 | 查看后台进度；大素材核验可能需数分钟，不要重复新建作业 |
| 模型请求失败或结果未知 | 先看原作业及页面恢复说明；仅使用页面明确提供的恢复或重新确认费用入口 |
| 素材离线或移动硬盘盘符变了 | 接回硬盘并“重新连接”，不要建立重复素材库 |
| 包装预览失效 | 核对当前设置，重新生成并观看真实预览，再确认方案 |
| 其他窗口已修改任务 | 刷新任务并核对最新内容，不要继续提交旧草稿 |
| 仅质检中断、视频没变 | 在返工中选“技术问题 → 仅重做质检（复用原视频）”；条件变化时按提示重新生成 |
| 上次导出没完成 | 恢复保存目录、空间或权限，再使用“继续上次导出” |
| 已导出的包缺文件 | 核对交付信息，点“重新导出完整交付包”；旧包保留 |
| 空间不足 | 在“设置 → 存储与缓存”先预览清理范围，再确认清理可重建缓存 |

修改文案、声音、镜头或包装后，旧批准不能自动用于新成片；按提示重新完成受影响步骤。只改封面或发布文字时，可沿用当前有效视频，重新导出交付包。

仍无法继续时，把任务名称、当前步骤、错误提示及所点按钮发给维护人员。不要附带密钥或带登录凭据的链接。

<a id="upgrade"></a>

## 14. 升级、回退和卸载

### 14.1 双击更新

日常升级使用原安装目录中的 **产品更新升级.bat**，不用重新添加 MCP，也不用移动任务文件。

1. 保存页面草稿，等待生成、渲染等任务完成。退出 WorkBuddy、豆包等已连接的助手。
2. 重启电脑后，**先运行产品更新升级.bat，再打开 CUTROOM**。关闭浏览器不会停止后台；升级入口会检查运行状态，不会强行结束任务。
3. 选择 **联网检查并下载新版**。无需 GitHub 账号；网络不通时，也可选择维护人员提供或自己已下载的官方 Windows ZIP。
4. 检查显示的当前版本和新版本，输入 **Y** 开始，等待“升级完成”。升级时不要打开 CUTROOM 或重新连接 MCP。
5. 从原来的 **启动CUTROOM.bat** 打开。在 WorkBuddy/豆包中重新连接一次 MCP，即可加载新版工具；不要删除连接重建。

**Beta.10 及更早版本没有升级入口：** 下载新版并解压到另一个文件夹，运行新包的 **产品更新升级.bat**，选择原安装目录，再选择刚下载的 ZIP。不要把新包手动覆盖到旧目录；升级完成后继续使用原目录。维护人员改过程序、使用开发版或更换过运行环境时，工具会停止并提示维护处理。

本入口只支持兼容的程序原位升级，任务、素材、成片、Windows 凭据和 MCP 配置保留。涉及数据库结构或依赖变化的版本由维护人员处理。首次切换到编译发行包后，旧预览可能需要重新生成；按页面重新检查，不把旧批准直接套到新结果。

升级失败时，按提示使用 **恢复上次未完成的升级**；中断期间不要启动工作台。程序备份在原安装目录的 `runtime/software-updates`。仍无法恢复时，保留现场并导出报错日志，交维护人员处理。

### 14.2 回退和卸载

不要让旧版直接打开已经由新版升级的数据。回退需要恢复升级前备份；卸载前先确认任务、成片、声音和素材都已保全。维护人员按[升级与恢复说明](../operations/cutroom-maintenance.md)执行。

<a id="agent-mode"></a>

## 可选：连接 WorkBuddy 或豆包工作

MCP 是让聊天助手调用 CUTROOM 工具的连接方式。连接后，你可以在 WorkBuddy 或豆包工作中查询任务、提交规划和使用已支持的剪辑建议；视频仍在本机 CUTROOM 中制作。只使用网页的同事不需要安装 MCP。

[连接前准备](#mcp-preparation) · [添加到 WorkBuddy](#mcp-workbuddy) · [添加到豆包工作](#mcp-doubao) · [连接故障](#mcp-troubleshooting)

<a id="mcp-preparation"></a>

### 连接前准备：只做一次

1. 先完成 CUTROOM 安装，并用 **启动CUTROOM.bat** 打开工作台，确认能看到自己的任务。
2. 找到这个工作台实际使用的安装目录，里面应有 `安装CUTROOM.bat`、`启动CUTROOM.bat` 和 `scripts` 文件夹。不要选源码下载目录、旧版目录或另一份测试安装。
3. 在该文件夹的资源管理器地址栏输入 `powershell`，按回车。复制下面的命令并执行，等待成功后再继续；首次需要联网。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-mcp.txt
```

**以下默认接入步骤适用于“同一安装目录、默认任务库、默认工作台端口 8765”。** 如果维护人员为你设置过独立任务库、自定义端口或多份安装，先由维护人员按实际实例配置，不要直接运行默认连接脚本。否则可能连到空库或另一批任务。已有 26/26 工具且任务正确的连接不用重新安装。

提示找不到 Python、缺少模块或安装失败时，保留错误窗口，交维护人员处理，不要删除 `.venv` 或任务目录。接入说明中的令牌只用于本机连接，不是豆包配音 API Key。

<a id="mcp-workbuddy"></a>

### 添加到 WorkBuddy

**首次添加：**

1. 在上一步的 PowerShell 窗口执行检查：

   ```powershell
   .\.venv\Scripts\python.exe scripts\probe-cutroom-mcp.py --client workbuddy
   ```

   看到 `ok: true`、`toolCount: 26`、`allowedTaskActionCount: 4` 后再继续。这一步使用临时库检查程序，不证明已经连接到你的任务。

2. 按 `Win + R`，输入 `%USERPROFILE%\.workbuddy` 并打开。若已有 `mcp.json`，在同一文件夹复制一份作为备份；尚无此文件可继续。
3. 回到 CUTROOM 目录的 PowerShell 窗口执行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\install-workbuddy-mcp.ps1
   ```

   脚本自动添加或更新 `cutroom`，保留其他 MCP；不需要再重复点击“添加 MCP”。

4. 打开 WorkBuddy 的 **MCP 服务管理**，找到 `cutroom`，打开启用开关；如果出现信任提示，确认后继续。已有该项时点击右侧 **↻** 或错误提示下的 **重连**。
5. 看到绿点和 **26/26 个工具已启用** 后，新建一个 WorkBuddy 会话。若仍显示旧数量，完全退出 WorkBuddy，再重新打开。
6. 在新会话发送下面这段检查指令，并核对返回的任务与你网页中的任务一致：

> 请通过 CUTROOM MCP 查询系统状态和已有任务，不创建任务、不修改内容、不执行生成。确认客户端身份为 workbuddy、工具数为 26、允许的任务动作数为 4，并列出已有任务供我核对。

**以后每天使用：** 打开同一份 CUTROOM 和 WorkBuddy 即可。MCP 程序由 WorkBuddy 启动，不需要另留一个 MCP 服务窗口。更新安装目录后，先由维护人员更新连接路径和任务库绑定，再点重连；仅重连不会自动下载或升级 CUTROOM。

<a id="mcp-doubao"></a>

### 添加到豆包工作

此流程用于与 CUTROOM 在**同一台电脑**上的豆包工作客户端，使用本地 HTTP 连接。豆包工作的 MCP 连接与 CUTROOM 设置里的“豆包配音账号”是两项独立配置。

**首次添加：**

1. 完成“连接前准备”。在 CUTROOM 安装目录的 PowerShell 窗口启动连接服务：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\start-doubao-work-mcp.ps1
   ```

   保持这个窗口开启。正常启动后会显示 `http://127.0.0.1:8766/mcp`；它是 MCP 地址，不是网页工作台地址。

2. 在同一安装目录**另开一个 PowerShell 窗口**，获取本机的连接信息：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\show-doubao-work-mcp-config.ps1
   ```

   输出的 `Authorization` 值包含本机访问令牌，只复制到下方连接器字段，不发给聊天助手或群聊，也不要截图分享。

3. 在豆包工作打开 **插件 · 技能 · 伙伴 → 新建自定义连接器**。入口名称随客户端版本可能不同；找“自定义连接器”或“MCP”添加入口，按字段填写：

   | 字段 | 填写内容 |
   | --- | --- |
   | 名称／服务器名称 | `cutroom` |
   | 传输类型 | `HTTP`（Streamable HTTP） |
   | 服务器 URL | `http://127.0.0.1:8766/mcp` |
   | 自定义 Header 名称 | `Authorization` |
   | 自定义 Header 值 | 上一步输出的完整 `Bearer …` 值，保留空格，不带 JSON 引号 |

   不要把整段 JSON 粘进一个字段。若客户端没有 HTTP、自定义 Header 或本地服务接入能力，先交维护人员核对客户端支持范围。

4. 保存并启用连接，确认能发现 **26 个工具**。新建会话后发送：

> 请通过 CUTROOM MCP 查询系统状态和已有任务，不创建任务、不修改内容、不执行生成。确认客户端身份为 doubao_work、工具数为 26、允许的任务动作数为 4，并列出已有任务供我核对。

5. 对照网页核对任务。工具数量正确但任务不同，仍属于连接目标错误，先不要创建或修改任务。

**以后每天使用：** 打开 CUTROOM 后，先运行第 1 步的启动命令，保持服务窗口开启，再使用豆包工作；连接信息未变化时无需重复添加。关闭服务窗口后连接会断开，重新启动服务再重连。停用时可按 `Ctrl + C` 关闭服务。

<a id="mcp-troubleshooting"></a>

### MCP 连接失败或工具数量不对

| 看到的情况 | 怎么处理 |
| --- | --- |
| WorkBuddy 显示 `Connection closed` 或红点 | 表示后台连接被关闭；请维护人员核对该连接实际使用的 Python、依赖和启动日志。修复后再点“重连”，不靠反复重连修复缺失依赖 |
| 仍显示 12/12 或 14 个工具 | 常见于旧目录或旧会话；核对连接路径、实际任务库及新版代码，再重连并新建会话。GitHub 更新不等于本地连接已更新 |
| 显示 26 个工具，但任务为空或不对 | 先停止任务操作，让维护人员核对工作台与 MCP 是否使用同一个任务库；不要重建同名任务来替代旧任务 |
| 显示已连接，但聊天提示找不到工具 | 确认已启用且完成信任，新建会话；必要时完全退出客户端再打开 |
| 豆包工作连接被拒绝 | 确认第 1 步的服务窗口仍在运行；检查地址与端口是否一致，端口冲突交维护人员处理 |
| 豆包工作提示 401／未授权 | 核对 `Authorization` 字段及完整 `Bearer …` 值，令牌必须来自当前这份安装；不要填配音 API Key |
| MCP 能查任务，但网页打不开 | 用匹配安装的启动入口打开网页；MCP 连接与网页启动独立，维护人员需核对返回的工作台地址 |

连接检查只查询本机服务和任务，不触发 CUTROOM 配音、视频生成或模型分析；聊天客户端自身的用量按其规则计算。

### 接好后怎样开始制作

创建新任务时选择 **当前 Agent 规划**。看到“等待 Agent 提交规划”后，回到所用客户端继续，再返回 CUTROOM 检查。原来由“CUTROOM 自己规划”的任务不会因接上 MCP 自动改成 Agent 模式。

Agent 模式负责文案与分镜等规划，配音、视频生成等生产服务仍使用 CUTROOM 中的账号，并可能计费。最终文案、画面顺序、包装方案和完整审片四步仍由你在网页确认，MCP 不代替这些确认。

Codex 接入、独立任务库绑定、HTTP 检测、回滚和维护命令见[Agent 客户端操作说明](../operations/cutroom-agent-mcp-clients.md)。未配置 Agent 时，直接使用“CUTROOM 自己规划”。


### 创建、草稿和后台检查（Beta.13）

创建分两步：选择类型、填写内容与素材。点击“创建任务并填写文案”后自动检查；无阻断或仅提示“下一页填写文案”时直接创建；目录离线等其他提醒仍须核对。素材初检在后台进行，文案页可以同时填写、保存和确认。初检刷新不会覆盖正在输入的文字；后续分镜仍须通过素材检查。

保存失败时，文案旁会持续显示“草稿尚未保存”。请先复制到记事本，勿把点击按钮当作保存成功。后台显示心跳超时且长时间无进展时，先保存工作或复制文案，关闭 CUTROOM 工作台服务后重新启动（仅刷新浏览器无效）。启动后会按租约恢复中断状态；有“继续素材检查”按钮时点击它。不要手工修改数据库，也不要对未知付费结果反复重试。

“读法与试听”用于已确认文案中的选中词句；未确认时，按钮旁和点击提示会说明操作顺序。后台作业优先参考本机同类完成记录估算耗时；没有记录且已有可计算进度时按当前速度估算。没有依据时显示已处理时间和数据不足说明，不承诺完成时间。

视觉分析兼容完整 JSON 对象外的一层 Markdown 代码围栏，随后仍检查 JSON 结构、必需字段和取帧证据；截断、重复键和夹杂解释的响应仍失败。此兼容不新增远程请求，不会自动重试付费分析。小样本检测通过不代表每条真实素材都能成功；旧失败项不会自动转成成功，需重新准备未完成项并确认费用。
