# CUTROOM 操作手册

**准备文案和素材，按五步完成短视频。** 数字人路线使用已有口播原声，广告路线由文案生成配音；两条路线都可以选镜头、加字幕和包装，审片后导出。

第一次使用从“安装与准备”开始；已经安装的同事可直接看“五步制作”。本手册适用于与它一起下载的安装包，具体更新内容见[发行页](https://github.com/qnwhageqlavs-jpg/cutroom-releases/releases)。

<a id="routes"></a>

## 先选适合你的路线

| 你已有的内容 | 选择路线 | 制作效果 |
| --- | --- | --- |
| 数字人口播 MP4 和对应文案 | 数字人混剪 | 保留原声，核对字幕，按需要插入实拍或图片，制作竖屏短片 |
| 广告文案、本地视频和图片 | 信息流广告混剪 | 选择声音、生成配音，按文案推荐镜头，制作横屏或竖屏广告 |

CUTROOM 不生成数字人形象；数字人口播需要事先准备。园区宣传片专用路线、自动生成补充视频暂未开放。交付的是 MP4，不是剪映原生可编辑工程；发布到平台需要你自行操作。

当前为 Beta 试用版。历史广告任务首次打开仍可能需要等待；AI 自动生成发布标题和简介尚未开放，可手工填写。AI 检查与编辑建议仅覆盖已取得的证据，仍需完整人工审片。数字、数量单位的读法替换尚未支持，普通词语请按下方“读法与试听”操作。

## 安装与准备

### 第一次安装

1. 打开[下载页](https://github.com/qnwhageqlavs-jpg/cutroom-releases/releases)，在 Assets 中下载名称含 **windows-x64** 的 ZIP。无需 GitHub 账号，不选 Source code。
2. 完整解压到固定、可写的文件夹，例如 **D:\CUTROOM**。不要直接在压缩包中运行。
3. 保持联网，双击 **安装CUTROOM.bat**。需要软件安装权限；等待提示“安装完成”。
4. 双击 **启动CUTROOM.bat**，等待工作台在浏览器中打开。
5. 按下面两节准备服务账号和素材，先做一条短片，导出并打开 MP4 检查。

需要 Windows 10/11 的 64 位电脑。首次安装会下载必要组件及约 500 MB 的本地语音识别模型，耗时受网络影响；提示失败时保留窗口，按提示处理后重新运行安装入口。不要把旧电脑的账号文件直接复制给同事，每位使用者应在自己的电脑上配置可用账号。

### 安装停住、失败或电脑没有 Microsoft Store

安装窗口会显示当前步骤和已等待时间。安装器给 winget 安装每个组件、npm 安装各留 20 分钟，pip 升级 10 分钟，Python 依赖安装 30 分钟；超过本步时限会停止该步骤及子进程并提示失败，不会自动反复下载。语音识别模型准备仍按窗口内的独立时限执行。

遇到超时或失败，先保留窗口和安装目录下 `runtime/install-temp/step-*.log` 日志，检查网络或请 IT 协助，处理后重新打开 **安装CUTROOM.bat**。不要同时开启多个安装窗口，也不要删除任务、素材或搬动 `.venv` 环境；如果提示专用 Python 环境不完整，按提示在新的短路径重新解压原安装包。

若没有 winget，且 Microsoft Store 无法使用或受公司策略限制，请 IT 通过公司批准的安装来源预装 **64 位 Python 3.11、受支持的 Node.js LTS、FFmpeg（含 ffprobe）**，并使这些程序可从 PATH 找到。完成后关闭原安装窗口，重新打开 **安装CUTROOM.bat**，继续创建 CUTROOM 专用环境、安装依赖和执行自检。Node.js 若不具备声音版本校验能力，安装器会明确提示更新 LTS。不要复制别台电脑的 `.venv`，也不要跳过自检。

### 以后每天使用

从同一安装文件夹双击 **启动CUTROOM.bat** 即可，不用记网址。提示未授权时也从这个入口重新打开。

关闭网页不会取消正在处理的任务。重新打开后可以查看进度；需要暂停或取消时，使用页面提供的操作。已经发出的 AI 请求仍可能产生费用。

## 首次设置：服务与音色

1. 打开 **设置 → AI 服务连接**，添加自己可用的服务账号。
2. 进入 **模型与配音**，为需要的功能添加配置，保存并检测。
3. 广告配音账号可先准备，也可在任务进入“文案与声音”步骤时配置；新建任务不要求配音服务或音色。
4. 文案策划服务可用后即可创建第一条任务。没有账号或不清楚该填什么，请负责服务账号的管理员协助。

| 功能 | 用在哪里 |
| --- | --- |
| 文案策划 | 推荐分镜；包装建议实际使用的服务以提交页面为准 |
| 配音与试听 | 广告配音；数字人沿用原视频声音 |
| 素材画面分析 | 识别素材内容、提供带画面依据的包装建议，以及可选的成片内容检查 |
| B-roll 画面 | 自动生成补充视频尚未接通工作台，不作为首次使用必填项 |

检测、试听、规划和分析可能按供应商规则收费。提交前看清页面的服务、发送内容和费用提示；不要因等待较久而重复点击。已分析的素材、已生成的可恢复结果可复用。

音色试听会先检查本机能否保存文件。若提示缓存无法写入、替换或清理，本次不会调用配音服务；先检查安装位置和写入权限，建议使用安装说明中的固定短路径。已有请求显示结果未知时，先核对原请求，不要反复生成。

新建任务会保留所选文案策划服务；广告的配音服务和本片音色在“文案与声音”步骤选择并保存。文案草稿可先独立保存；音色保存失败会单独提示，确认文案和生成配音前仍需选择可用的声音。后来改变默认模型或常用音色，不会自动替换旧任务的声音和结果。有资源包的账号，请管理员为**已验证用途**选择适用模型；有额度不代表它适合所有画面或声音任务。

### 豆包配音账号

设置中的 **API Key** 用于生成、试听和检测；**AK/SK** 用于读取音色目录。只按账号实际开通情况填写，旧版账号的 AppID 与 Access Token 只用于兼容。

“保存并检测”会生成极短测试声音，可能计费。成功后不用重复检测。音色为空或提示无权限时，先检查账号权限，再刷新目录。密钥只填在本机设置中，不发群聊、不截图分享。管理员可参考安装包内的服务配置说明（docs/operations/model-profiles-new-api.md）。

## 把素材整理好，再开始制作

1. 在电脑或移动硬盘上整理文件夹，给项目画面、通用补充画面取清楚的名称。
2. 打开 **镜头素材**，新建或登记素材库并选择文件夹，等待扫描完成。
3. 选择本次需要的素材做本机检测；需要按画面内容自动匹配时，再按页面发起 **AI 内容分析**。
4. 创建视频任务时，只选择这条片会用到的素材范围。

**登记是让软件找到文件，内容分析是让软件了解画面。** 只扫描文件夹还不能保证按文案选出合适片段。分析前会说明使用的服务和发送范围；不用为了重复查看列表再次分析。

登记不会移动或重命名原片。后来新增文件，点击 **检查更新**；移动硬盘盘符或文件夹位置变化，使用 **重新连接**，不要删除后重建素材库。制作期间保持硬盘在线。

### 素材很多时怎样用

先按项目和用途限定范围，再搜索或筛选候选，不用一条片遍历所有文件。已有分析可以复用。缩略图、原片预览和取用时间帮助你判断素材是否合适；文件名或 AI 描述不能代替实际查看。

### 素材使用范围与隐私

通用库素材只能作示意，不能证明本园区或本项目的实际情况。明确要求项目画面或实拍时，系统会排除通用候选；没有合适项目素材就保留缺口。刷新时，旧的自动误选会被移回缺口；你已人工固定的镜头不会自动替换，仍需自行核对素材真实性。

使用模型做包装建议、创意建议或审片前，系统会再次核对实际使用素材的当前范围与隐私标记，包括数字人口播和已启用的包装素材。素材被撤出任务范围或标为禁止外发后，相关模型请求会停止；改了文件名或复制到包装目录也不能绕过检查。未使用的备选素材、禁用的包装项不会因此阻断本片检查。

如果旧成片缺少可核对的素材来源，模型检查会暂停；你仍可在本机播放和人工查看。先按提示核对来源及授权，再决定是否重新制作，不要为通过检查取消真实的隐私限制。请求尚未发送时不会记作已调用；已有部分请求发送后才停止的，已发生的调用仍可能计费，系统不会自动重发。

## 五步制作：先做通一条短片

在任务中心点击新建视频，选择路线、素材范围和画幅。数字人另选已有口播 MP4；广告在后续填写文案和选择声音。创建前的检查会指出素材离线、视频不可用或空间不足等需要处理的问题。

| 步骤 | 数字人 | 信息流广告 |
| --- | --- | --- |
| 1 | 口播核对 | 文案与配音 |
| 2 | 补充画面 | 分镜推荐 |
| 3 | 粗剪调整 | 粗剪调整 |
| 4 | 包装与审片 | 包装与审片 |
| 5 | 交付导出 | 交付导出 |

主推进按钮在步骤底部。顶部步骤条可以回看已完成步骤；回看不会自动改写结果。需要继续当前制作时点 **返回当前步骤**。任务列表可独立滚动，折叠侧栏可给编辑区留出更多空间。

创建中断或响应较慢时，先回任务列表看是否已经创建；不要连续新建同名任务。系统会保留能够核对的创建记录，按页面提示继续。

### 1. 确认文案与声音

**数字人：**

1. 填写与口播视频一致的完整文案，点击 **确认文案，开始核对**，等待本机识别完成。
2. 播放原声。对识别提示的疑点，点击对应项回听；一致就点 **确认本处一致**，不一致就记录问题并修改文案或底片。
3. 疑点处理后，点击 **确认与口播一致，继续**。逐项确认不能代替这次整体确认。

“粘贴 / 修改原文”可以编辑全文；原视频信息、换底片和核对记录在工作区上方。修改后保存，再按提示重新核对。数字人使用原声，不会因为改了几个字就改变原视频里说的话。

**广告：**

1. 填写最终文案，通读数字、单位、地点和联系方式。
2. 选择本片配音服务与音色，按需试听。
3. 点击 **确认文案，继续**，再按页面提示完成配音及分镜处理。视频时长以实际声音为准。

保存草稿不等于确认。已经确认的文案使用 **修改文案** 返工；保存前会说明影响哪些后续步骤。广告新稿需要匹配的新配音，旧版声音和已导出文件保留。

### 2. 按文案选择画面

广告的 **分镜推荐** 会为各段旁白初选画面。数字人的 **补充画面** 用于在口播中安排实拍或图片；不需要补充时可以保留人物。

1. 发起页面提供的推荐操作，先核对发送范围与费用。
2. 对照每段文案，播放候选原片，检查画面内容及取用位置。
3. 不合适就更换；只点击候选是预览，按 **使用这段画面** 或对应应用按钮才会替换。
4. 选好后点击 **生成粗剪**。

数字人补充画面不改变这段口播声音或总时长。广告每段都需要有可用、时长足够的画面。素材太短可以换长片段或合适图片；不能只靠反复推荐解决缺素材。

有已生成但未保存完成的结果时，优先用 **恢复已生成分镜**。输入仍一致时，软件可继续处理已有结果，避免重复调用；文案或素材已经改变时按提示重新处理。

### 3. 粗剪调整

左侧选择镜头，中间预览，右侧查看来源和修改。先连续播放，再检查单个镜头。数字人保留口播主声，补充镜头原声通常静音。

- **更换镜头：** 预览候选后确认应用。广告候选的横屏、竖屏及“与本片同向”按实际展示尺寸判断，不按文件名猜测；数字人任务使用竖屏画面，旋转信息也计入判断。方向未知时先检测素材，错向或方形素材需换成同向画面。旧任务可逐个修正，全部有效后才能锁定画面；Logo和贴纸不受全屏素材方向限制。
- **调整取用区间：** 选择原片从哪里开始、在哪里结束。提示越界或太短时先修正。
- **调整安排：** 使用当前页面允许的添加、删除、顺序调整和撤销操作。
- **更新自动选材：** 有了新的素材分析后，可在尚未锁定且页面允许时更新自动推荐；手工修改会保留。
- **兼容预览：** 浏览器不能直接播放某种素材时，按提示生成本片兼容预览，完成后再看。不改变原素材，也不调用 AI。

核对完成后点 **确认粗剪并锁定画面**。正在核验时等待即可；重复画面、文件变化或缺失会给出处理提示。

### 4. 包装与审片

**先调整包装：** 选择字幕样式、背景音乐，以及需要的标题、信息卡、Logo、贴纸和花字。左侧选项目，中间看画面，右侧修改文字和样式。改完先保存或应用。

“一键生成整套包装”会按页面显示的服务和费用发起建议。两种生成风格决定元素的密度：

- **简洁商务：** 实拍为主，统一字幕与音乐，最多一个开场标题、两处事实信息卡。
- **重点突出：** 沿用同一套标题、字幕和卡片排版，按内容增加少量花字等强调；同一信息避免反复出现。

新建议从已确认文案中选取短标题和事实，仍须核对是否准确、是否遮挡主体。历史方案和人工调整保留，不会因升级自动换成新样式。跨任务使用模板后，重新核对本片文字。

选择花字、标题或信息卡样式会立即改变中央的静态示意；字幕字体也可即时查看。点击“应用并定位”或“保存设置”才保存修改，取消保留原设置。字体、光晕、动效及组合效果以保存后生成的真实预览和成片为准。**不需要为了进入成片步骤再完整看一遍包装预览。**

点击生成成片的主按钮，等待制作和检查。AI 检查尚未配置或失败，不等于视频生成失败；页面会分别显示。需要 AI 检查时先处理服务问题，再返回当前成片开始检查。

**再检查成片：**

1. 在 **检查成片** 播放当前版本，完整看画面、字幕和声音。
2. 左侧选检查问题，右侧查看原因；有问题点 **去修改**。
3. 实际可接受时点 **已核对，保留现状** 并提交。多项共用同一原因时，勾选左侧项目后点 **批量核对**；只切换当前问题不代表已经多选。
4. 核对观看进度、待处理项和人工核对声明，再点 **确认成片，进入交付**。

AI 建议可能有误，听感证据不足也不是声音已经通过。最终确认由你完成。观看达到 100% 但按钮仍灰色时，先检查是否仍有未提交的问题处理或未勾选声明，不必立即重看整片。

### 5. 导出并取用

1. 核对当前成片版本和保存位置；需要时点 **更换目录**。
2. 点击 **导出交付包**。封面、标题、说明和话题按需补充，不制作封面也可先导出视频。
3. 完成后点打开导出文件夹的按钮，找到 MP4 并播放一次。
4. 展开文件清单可查看这次附带的封面、文字、检查报告和版本记录。

封面可用素材图片加标题进行本地排版，保存高清 JPG；不调用图片生成服务。平台发布文字用于复制到发布平台，不会修改视频，也不会自动发布。附带“待补”标记的封面或文字需要补齐，不能当作已经审核的发布内容。

## 改读法、换声音和处理配音等待

数字、数量单位的读法替换尚未支持；遇到这类读音问题，请先调整文案表达并重新试听，不要直接套用普通词语的读法替换。

| 你想做什么 | 操作 |
| --- | --- |
| 纠正某个词的读法 | 选中文案中的词句，点“读法与试听”，试听后应用 |
| 更换本片音色 | 点“更换本片音色”，选声音、生成试听，确认满意后再应用 |
| 试听已生成，但镜头时长不够 | 选“保留试听，先调整画面”，调整后重新打开并找回上次试听 |
| 请求一直显示结果未知 | 打开原任务配音编辑器，选择“找回上次试听”，先核对原请求 |
| 本机有完整、匹配的声音结果 | 使用“恢复本机已有配音”，试听后再明确应用，不会再次生成收费 |
| 没有可恢复结果 | 阅读原请求费用未知的提示，选择“结束旧请求等待”；之后是否重新生成由你决定 |

声音改变可能影响片长。应用后按提示重新检查画面、包装与成片；旧版交付保留。文案或服务已经变化时，旧试听不能直接应用到新版本。

<a id="text-edit"></a>

## 改片：使用页面返工，不删旧任务

已完成任务从交付页点 **修改视频**，选择要改的内容。只改封面或发布文字，使用 **修改交付信息**，无需重新生成视频。

| 修改内容 | 之后需要做什么 |
| --- | --- |
| 数字人文案或口播底片 | 重新确认文案、核对原声，再检查后续镜头 |
| 广告文案或声音 | 重新确认并试听声音，再检查镜头时长 |
| 镜头或取用位置 | 重新预览并确认粗剪 |
| 字幕、标题、音乐等包装 | 保存包装并生成新成片，再审片 |
| 封面和发布文字 | 核对后重新导出相应交付 |

原成片和旧交付会保留；新版本不能沿用旧版的观看确认。把文案改回原来的文字，也需要按当前版本完成确认。

粗剪中的文字修改用于辅助提出编辑意图。先查看解析出的修改内容和影响，再确认；不清楚时用页面上的更换镜头、调整区间等操作更直接。

<a id="gaps"></a>

## 没有合适镜头时怎么办

打开 **查看缺口处理清单**，定位到具体文案段：

- 数字人可以保留原人物画面，不必强行加补充镜头。
- 广告需要可用画面，可更换片段、补充照片或加入新的素材目录。
- 素材离线先重新连接；尚未分析先按页面完成检测和内容分析。
- 通用园区或城市画面可以补充氛围，但不能证明旁白中的具体设施、租金或政策。
- AI 补拍建议只是建议，当前工作台不会自动把缺口生成为新视频。

“节奏检查与建议”提供本地检查和可选 AI 建议。本地检查不调用 AI；AI 建议提交前要核对服务、发送范围和费用。刷新已有结果不会重新生成建议。

<a id="packaging"></a>

## 常用包装、音乐与封面

在 **包装素材** 中按类别管理音色、字幕样式、音乐、音效、贴纸和 Logo。点击项目查看效果或试听，再在任务中选用。

- 个人样式可从已有样式修改后另存，原样式保留。
- 添加音乐、音效或图片会登记到个人素材中；具体出现时间和位置仍在任务里设置。
- 配音样音需要服务生成时可能计费，已有样音可以直接播放。
- 设计封面时检查标题不要遮挡人物或重要内容；成片版本改变后，为新版本重新核对封面。

<a id="asset-tools"></a>

## 查找素材、改任务范围与导出清单

在 **镜头素材** 中先选素材库，再搜索、筛选或切换缩略图和列表。点文件查看片段；一个视频可能有多个片段，片段数不等于文件数。

任务顶部 **任务详情** 中可以查看本次素材范围。通过其中修改素材目录的入口调整范围；正在处理或画面已锁定时，按页面提示先完成或返工。改变补充素材目录不会替换数字人口播底片。

需要多人整理素材描述时，可使用页面提供的 Excel 台账导出与导入，按原表结构填写，再查看导入结果。不要把手动改文件名当作重新连接。 人工修正镜头方向后，受影响的相邻衔接需要重新核对；已保存的任务和成片不会被导入静默改写。数字人从补充画面切回原画面也参加衔接检查，连续播放同一段原画面不会因文案分段重复提示。 旧任务原始口播缺少方向记录时，编辑画面或重新生成会先读取已绑定的源文件检测；检测失败请恢复原文件后再试。 修改镜头前，确认框会列出各方案中相关的标题、信息卡或音效，提醒核对出现时间和位置；这不会自动改写包装或重做配音。

<a id="ai-review"></a>

## 怎样理解 AI 检查

技术检查判断成片能否正常使用；AI 内容与声音检查提供可能需要核对的问题；人工审片决定是否接受当前成片。三者在页面上分别显示。

AI 未运行或服务中断会如实保留。你仍须完成必要的技术检查、问题处理和人工声明；不能把“没有检查结果”当作“没有问题”。AI 检查可发送抽样画面、相关文案和声音检查所需内容，具体以提交前提示为准。

<a id="checklist"></a>

## 第一条片和正式发布前检查

- 文案中的数字、单位、地点、政策和承诺准确。
- 画面能对应旁白，通用素材没有被当成具体事实证明。
- 字幕清楚，没有挡住人物或重要信息；标题和信息卡没有挤在一起。
- 发音、音量、背景音乐和镜头衔接可接受。
- 当前成片已完整观看，问题处理已经提交。
- 导出的 MP4 能在普通播放器中打开，封面和发布文字已补齐或明确不使用。

目前没有可统一承诺的“创建到导出只需几分钟”成绩。素材准备、首次分析、片长、电脑、AI 服务和返工都会影响总时间；页面进度供安排等待，人工检查时间也要计入。

<a id="troubleshooting"></a>

## 遇到问题怎么办

| 看到的情况 | 先这样处理 |
| --- | --- |
| 安装未完成或窗口报错 | 保留错误信息，处理网络或安装权限后重试；仍失败请维护人员协助 |
| 第一次打开历史任务较慢 | 等待加载，不反复开同一任务；持续无响应时导出日志 |
| 视频黑屏或载入失败 | 在“播放异常？”中重新载入，恢复后点击播放；会保留已保存的观看记录 |
| 旧版本文件缺失 | 返回当前可用成片；反复重新载入不能找回被删文件 |
| 素材目录离线 | 接回硬盘，盘符或位置改变时使用“重新连接” |
| 转写文件损坏或缺失 | 使用“保留原件并重新转写”，完成后重新核对；原视频也变化时先换底片 |
| 分镜或生成中断 | 先看处理详情；有已有结果时使用恢复或继续入口，避免重复 AI 调用 |
| 配音结果未知 | 按“改读法、换声音和处理配音等待”核对原请求 |
| 分镜提示仍有画面待补 | 点击底部“待补画面”，逐段选好素材；全部补齐后重新点击“生成粗剪”核验 |
| 提示分镜或素材范围已变化 | 核对当前安排后发起新核验；不要继续旧版本的核验，反复刷新不能补齐素材 |
| 包装预览过期 | 保存当前设置，需要预览时重新生成；正式生成后完整审看新成片 |
| AI 检查失败、余额不足或需要检测 | 在设置里处理服务问题再重试；失败不等于视频内容不合格，也不会记作通过 |
| 看完了仍不能确认成片 | 查看待处理问题是否都已提交、声明是否勾选、观看记录是否保存 |
| 导出失败 | 查看原因，检查空间和保存目录；处理后点“继续上次导出”，不用重新制作视频 |
| 任务突然为空或提示记录缺失 | 停止新建和清理，保留安装目录，请维护人员恢复；不要删除备份 |

重新载入视频会尽量回到原位置，并保留倍速、音量与静音设置。它不会代为补全观看或批准。原始文件损坏、缺失时，先处理文件问题。

<a id="agent-mode"></a>

## 可选：连接 WorkBuddy 或豆包工作

MCP 是让聊天助手调用 CUTROOM 工具的连接方式。连接后，你可以在 WorkBuddy 或豆包工作中查询任务、提交规划和使用已支持的剪辑建议；视频仍在本机 CUTROOM 中制作。只使用网页的同事不需要安装 MCP。

[连接前准备](#mcp-preparation) · [添加到 WorkBuddy](#mcp-workbuddy) · [添加到豆包工作](#mcp-doubao) · [连接故障](#mcp-troubleshooting)

<a id="mcp-preparation"></a>

### 连接前准备：只做一次

1. 先完成 CUTROOM 安装，并用 **启动CUTROOM.bat** 打开工作台，确认能看到自己的任务。
2. 找到这个工作台实际使用的安装目录，里面应有 `安装CUTROOM.bat`、`启动CUTROOM.bat` 和 `scripts` 文件夹。不要选源码下载目录、旧版目录或另一份测试安装。
3. 在该文件夹的资源管理器地址栏输入 `powershell`，按回车。复制下面的命令并执行，等待成功后再继续；首次需要联网。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-mcp.txt
```

**以下默认接入步骤适用于“同一安装目录、默认任务库、默认工作台端口 8765”。** 如果维护人员为你设置过独立任务库、自定义端口或多份安装，先由维护人员按实际实例配置，不要直接运行默认连接脚本。否则可能连到空库或另一批任务。已有 26/26 工具且任务正确的连接不用重新安装。

提示找不到 Python、缺少模块或安装失败时，保留错误窗口，交维护人员处理，不要删除 `.venv` 或任务目录。接入说明中的令牌只用于本机连接，不是豆包配音 API Key。

<a id="mcp-workbuddy"></a>

### 添加到 WorkBuddy

**首次添加：**

1. 在上一步的 PowerShell 窗口执行检查：

   ```powershell
   .\.venv\Scripts\python.exe scripts\probe-cutroom-mcp.py --client workbuddy
   ```

   看到 `ok: true`、`toolCount: 26`、`allowedTaskActionCount: 4` 后再继续。这一步使用临时库检查程序，不证明已经连接到你的任务。

2. 按 `Win + R`，输入 `%USERPROFILE%\.workbuddy` 并打开。若已有 `mcp.json`，在同一文件夹复制一份作为备份；尚无此文件可继续。
3. 回到 CUTROOM 目录的 PowerShell 窗口执行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\install-workbuddy-mcp.ps1
   ```

   脚本自动添加或更新 `cutroom`，保留其他 MCP；不需要再重复点击“添加 MCP”。

4. 打开 WorkBuddy 的 **MCP 服务管理**，找到 `cutroom`，打开启用开关；如果出现信任提示，确认后继续。已有该项时点击右侧 **↻** 或错误提示下的 **重连**。
5. 看到绿点和 **26/26 个工具已启用** 后，新建一个 WorkBuddy 会话。若仍显示旧数量，完全退出 WorkBuddy，再重新打开。
6. 在新会话发送下面这段检查指令，并核对返回的任务与你网页中的任务一致：

> 请通过 CUTROOM MCP 查询系统状态和已有任务，不创建任务、不修改内容、不执行生成。确认客户端身份为 workbuddy、工具数为 26、允许的任务动作数为 4，并列出已有任务供我核对。

**以后每天使用：** 打开同一份 CUTROOM 和 WorkBuddy 即可。MCP 程序由 WorkBuddy 启动，不需要另留一个 MCP 服务窗口。更新安装目录后，先由维护人员更新连接路径和任务库绑定，再点重连；仅重连不会自动下载或升级 CUTROOM。

<a id="mcp-doubao"></a>

### 添加到豆包工作

此流程用于与 CUTROOM 在**同一台电脑**上的豆包工作客户端，使用本地 HTTP 连接。豆包工作的 MCP 连接与 CUTROOM 设置里的“豆包配音账号”是两项独立配置。

**首次添加：**

1. 完成“连接前准备”。在 CUTROOM 安装目录的 PowerShell 窗口启动连接服务：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\start-doubao-work-mcp.ps1
   ```

   保持这个窗口开启。正常启动后会显示 `http://127.0.0.1:8766/mcp`；它是 MCP 地址，不是网页工作台地址。

2. 在同一安装目录**另开一个 PowerShell 窗口**，获取本机的连接信息：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\show-doubao-work-mcp-config.ps1
   ```

   输出的 `Authorization` 值包含本机访问令牌，只复制到下方连接器字段，不发给聊天助手或群聊，也不要截图分享。

3. 在豆包工作打开 **插件 · 技能 · 伙伴 → 新建自定义连接器**。入口名称随客户端版本可能不同；找“自定义连接器”或“MCP”添加入口，按字段填写：

   | 字段 | 填写内容 |
   | --- | --- |
   | 名称／服务器名称 | `cutroom` |
   | 传输类型 | `HTTP`（Streamable HTTP） |
   | 服务器 URL | `http://127.0.0.1:8766/mcp` |
   | 自定义 Header 名称 | `Authorization` |
   | 自定义 Header 值 | 上一步输出的完整 `Bearer …` 值，保留空格，不带 JSON 引号 |

   不要把整段 JSON 粘进一个字段。若客户端没有 HTTP、自定义 Header 或本地服务接入能力，先交维护人员核对客户端支持范围。

4. 保存并启用连接，确认能发现 **26 个工具**。新建会话后发送：

> 请通过 CUTROOM MCP 查询系统状态和已有任务，不创建任务、不修改内容、不执行生成。确认客户端身份为 doubao_work、工具数为 26、允许的任务动作数为 4，并列出已有任务供我核对。

5. 对照网页核对任务。工具数量正确但任务不同，仍属于连接目标错误，先不要创建或修改任务。

**以后每天使用：** 打开 CUTROOM 后，先运行第 1 步的启动命令，保持服务窗口开启，再使用豆包工作；连接信息未变化时无需重复添加。关闭服务窗口后连接会断开，重新启动服务再重连。停用时可按 `Ctrl + C` 关闭服务。

<a id="mcp-troubleshooting"></a>

### MCP 连接失败或工具数量不对

| 看到的情况 | 怎么处理 |
| --- | --- |
| WorkBuddy 显示 `Connection closed` 或红点 | 表示后台连接被关闭；请维护人员核对该连接实际使用的 Python、依赖和启动日志。修复后再点“重连”，不靠反复重连修复缺失依赖 |
| 仍显示 12/12 或 14 个工具 | 常见于旧目录或旧会话；核对连接路径、实际任务库及新版代码，再重连并新建会话。GitHub 更新不等于本地连接已更新 |
| 显示 26 个工具，但任务为空或不对 | 先停止任务操作，让维护人员核对工作台与 MCP 是否使用同一个任务库；不要重建同名任务来替代旧任务 |
| 显示已连接，但聊天提示找不到工具 | 确认已启用且完成信任，新建会话；必要时完全退出客户端再打开 |
| 豆包工作连接被拒绝 | 确认第 1 步的服务窗口仍在运行；检查地址与端口是否一致，端口冲突交维护人员处理 |
| 豆包工作提示 401／未授权 | 核对 `Authorization` 字段及完整 `Bearer …` 值，令牌必须来自当前这份安装；不要填配音 API Key |
| MCP 能查任务，但网页打不开 | 用匹配安装的启动入口打开网页；MCP 连接与网页启动独立，维护人员需核对返回的工作台地址 |

连接检查只查询本机服务和任务，不触发 CUTROOM 配音、视频生成或模型分析；聊天客户端自身的用量按其规则计算。

### 接好后怎样开始制作

请让已连接的助手通过 CUTROOM 创建使用 **当前 Agent 规划** 的新任务。看到“等待 Agent 提交规划”后，回到所用客户端继续，再返回 CUTROOM 检查。原来由“CUTROOM 自己规划”的任务不会因接上 MCP 自动改成 Agent 模式。

Agent 模式负责文案与分镜等规划，配音、视频生成等生产服务仍使用 CUTROOM 中的账号，并可能计费。最终文案、画面和成片仍由你在网页核对并确认，MCP 不代替这些确认。

Codex 接入、独立任务库绑定、HTTP 检测、回滚和维护命令见安装包内的 Agent 客户端操作说明（docs/operations/cutroom-agent-mcp-clients.md）。未配置 Agent 时，直接使用“CUTROOM 自己规划”。
